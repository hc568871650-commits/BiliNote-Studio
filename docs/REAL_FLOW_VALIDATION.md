# 真实流程验收

本项目已获用户授权进行开发验收所必需的真实模型/API调用。模拟、替身、固定响应和故障注入是补充回归，不代替真实业务流程。本文件规定执行方法，不代表任何一次测试已经通过；实际结果写入对应交付目录。

## 执行步骤

1. 阅读 `AGENTS.md`、`DEVELOPMENT.md` 和 `docs/PREVIEW_STATUS.md`。核实当前源码、配置、服务归属，确定独立前后端端口、前端API地址、应用身份、数据与缓存目录，确保不会写入正式安装或工作区外预览。使用独立测试配置，凭据仅在本地读取和使用。
2. 选择已有配置中正常可用的模型及其真实协议；使用短小、非私人的真实素材，设置与任务相称的输出上限和有限请求预算。调用前说明测试范围与预计调用，不为已授权的普通必要API调用反复请求确认。
3. 从实际应用入口提交业务任务，经过真实后端与真实模型调用，观察任务阶段及请求受理结果，核查生成正文、版本、索引和诊断记录。重新打开结果，检查界面确实读取已保存内容。若目标包含全文查找、命中定位、诊断或恢复，再沿实际界面完成对应操作。
4. 按本轮改动验证必要分支：成功、模型失败、正文/索引保存失败、提交结果未知，以及适用的重试保存、重新生成、切换任务和重复点击保护。难以稳定触发的故障可用注入辅助，但应单列为故障注入证据；实际模型请求与真实持久化成功链路仍须验证。恢复保存不应重复调用模型，重新生成应明确记录新增请求。
5. 检查每个关键阶段是否真实执行：来源获取、字幕/音频转写、模型生成、正文保存、索引保存、UI读取。实际复用缓存或已有字幕时写明来源和跳过阶段；测试本地素材不能证明远程下载可用。任一关键阶段为mock、固定响应或替身时，标注缺口并补验，不能称为完整真实流程。
6. 阅读问答/图片功能从实际阅读界面加入附件并明确发送，使用内容不写在文件名、alt或问题里的非私人样本；核对画廊选择、图像哈希、草稿保留、真实回答、刷新后历史与适用的续问。只验证HTTP状态不足以判断流式成功，须检查SSE错误和最终完成。合成输入素材可以提供明确预期，但模型回答不得用固定响应代替。
7. 留存下方记录和证据，按预览生命周期规则收尾；真实请求、生成、保存仍在执行时不得为清理而停止服务。实际入口、保留服务及关闭记录更新到预览清单，由本轮交付说明验证边界。

## 每次验收记录

记录保存至本轮 `docs/<主题-日期>/`，运行数据和含私人内容的产物留在独立测试目录，不提交仓库。

| 项目 | 必须记录的内容 |
| --- | --- |
| 环境 | 源码版本或改动范围、应用入口、前后端端口、独立数据/缓存目录、开始结束时间 |
| 素材与链路 | 素材来源及非私人属性；每个阶段实际执行、缓存复用、已有字幕、故障注入或尚未验证的情况 |
| 请求 | 实际端点（脱敏）、服务商、模型ID、实际协议、输出上限；逻辑请求数与HTTP尝试数，区分首次、重新生成、兼容重试及仅保存恢复 |
| 返回 | 成功/失败、阶段、脱敏错误与request ID；输入/输出/思考/缓存用量（服务商未返回则记未知），有依据时记录费用 |
| 结果 | 任务ID、版本ID、正文/索引/诊断等结果文件位置，重开读取及用户操作结果；只保留可公开的证据内容 |
| UI证据 | 实际应用页面的截图或交互记录，覆盖提交、阶段、结果读取及本轮目标；合成页面单列说明 |
| 结论 | 按真实成功链路、真实失败链路、故障注入、静态/单元检查分别列结果，明确未验证阶段与剩余问题 |

不得输出API Key、Authorization、Cookie或完整敏感请求/响应；截图前检查敏感信息。失败先定位原因，再有限重试或调整方法，不能通过悄悄更换模型、协议、素材或mock来获得“通过”。端点可用或单独HTTP模型调用成功，只证明该检查范围，不等于实际应用完整流程通过。
